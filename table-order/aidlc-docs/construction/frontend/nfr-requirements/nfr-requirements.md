# NFR Requirements - Unit 2 (Frontend)

## 1. 성능 요구사항

| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| 초기 페이지 로드 (FCP) | 3초 이내 | Lighthouse |
| 인터랙션 응답 | 1초 이내 | 사용자 체감 |
| JavaScript 번들 크기 | 페이지당 200KB 이내 (gzip) | 빌드 분석 |
| 이미지 로딩 | Lazy loading 적용 | 뷰포트 진입 시 로드 |
| SSE 이벤트 수신 → UI 반영 | 500ms 이내 | 이벤트 타임스탬프 비교 |

### 성능 전략
- Next.js 자동 코드 스플리팅 활용
- 이미지 lazy loading (외부 URL이므로 `<img loading="lazy">`)
- React.memo / useMemo로 불필요한 리렌더링 방지
- 장바구니 상태 변경 시 관련 컴포넌트만 리렌더링

## 3. 네트워크 복원력 (PWA)

### Service Worker 전략
| 리소스 | 캐싱 전략 | 설명 |
|--------|----------|------|
| HTML/JS/CSS (앱 셸) | Cache First | 앱 기본 구조 오프라인 사용 가능 |
| 메뉴 데이터 | Network First, Cache Fallback | 최신 데이터 우선, 오프라인 시 캐시 |
| 메뉴 이미지 | Cache First | 한번 로드 후 캐시에서 제공 |
| API 요청 (주문 등) | Network Only + Queue | 오프라인 시 큐에 저장, 복구 시 전송 |

### 오프라인 동작
| 상황 | 동작 |
|------|------|
| 메뉴 조회 (오프라인) | 캐시된 메뉴 데이터 표시 + "오프라인" 배너 |
| 장바구니 조작 (오프라인) | 정상 동작 (로컬 상태) |
| 주문 생성 (오프라인) | "네트워크 연결 필요" 안내 + 장바구니 유지 |
| SSE 연결 끊김 | 재연결 시도 + "실시간 업데이트 일시 중단" 표시 |
| 네트워크 복구 | 자동 재연결 + 데이터 동기화 |

### PWA 매니페스트
- `display: standalone` (앱처럼 동작)
- 홈 화면 추가 가능
- 오프라인 폴백 페이지 제공

## 4. 접근성 요구사항 (기본 수준)

| 항목 | 요구사항 |
|------|---------|
| 시맨틱 HTML | `<header>`, `<nav>`, `<main>`, `<button>` 등 적절한 태그 사용 |

| 이미지 alt | 메뉴 이미지에 메뉴명 alt 텍스트 |
| 포커스 표시 | 포커스 가능 요소에 시각적 포커스 링 |

## 5. 사용성 요구사항

### 터치 인터페이스
| 항목 | 요구사항 |
|------|---------|
| 터치 타겟 크기 | 최소 44x44px |
| 터치 간격 | 인접 터치 타겟 간 최소 8px 간격 |
| 스와이프 | 카테고리 전환 시 좌우 스와이프 지원 (선택) |

| 피드백 | 터치 시 시각적 피드백 (ripple/scale 효과) |

### 반응형 레이아웃
| 앱 | 모바일 | 태블릿 | 데스크톱 |
|----|--------|--------|---------|
| 고객앱 메뉴 | 1열 카드 | 2열 카드 | 3열 카드 |
| 고객앱 장바구니 | 풀 화면 | 풀 화면 | 사이드 패널 |
| 관리자 대시보드 | 2열 그리드 | 3열 그리드 | 4열 그리드 |
| 관리자 사이드바 | 하단 탭바 | 좌측 사이드바 | 좌측 사이드바 |

## 6. 보안 요구사항 (Frontend 관점)

| 항목 | 요구사항 |

| 토큰 저장 | localStorage (HttpOnly 쿠키 대안 고려 가능) |

| API 키 | 클라이언트에 노출되는 키 없음 (서버 프록시) |
