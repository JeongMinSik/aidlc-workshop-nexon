# Frontend Business Rules - Unit 2

## 1. 장바구니 규칙

### 검증 규칙
| 규칙 | 조건 | 동작 |
|------|------|------|
| 빈 장바구니 주문 불가 | items.length === 0 | 주문 버튼 비활성화 |
| 수량 최소값 | quantity < 1 | 항목 자동 삭제 |
| 수량 최대값 | quantity > 99 | 99로 제한 |
| 가격 표시 | 항상 | 원(₩) 단위, 천 단위 콤마 |

### 장바구니 동작 규칙
| 상황 | 동작 |
|------|------|
| 같은 메뉴 재추가 | 수량 +1 (새 항목 생성 안 함) |
| 수량 0으로 감소 | 항목 자동 삭제 |
| 주문 성공 | 장바구니 비우기 + localStorage 삭제 |
| 주문 실패 | 장바구니 유지 |
| 페이지 새로고침 | localStorage에서 복원 |
| 세션 만료 | 장바구니 유지 (재로그인 후 사용 가능) |

## 2. 인증 규칙

### 고객앱 (테이블 태블릿)
| 규칙 | 조건 | 동작 |
|------|------|------|
| 자동 로그인 | 저장된 인증 정보 존재 | 자동 로그인 시도 |
| 로그인 실패 | 인증 정보 불일치 | 에러 표시, 설정 화면 이동 |
| 토큰 만료 | API 401 응답 | 자동 재로그인 시도 |
| 재로그인 실패 | 비밀번호 변경 등 | 설정 화면 이동 |

### 관리자앱
| 규칙 | 조건 | 동작 |
|------|------|------|
| 로그인 필수 | 토큰 없음 | 로그인 화면 리다이렉트 |
| 세션 만료 | 16시간 경과 | 자동 로그아웃 + 안내 메시지 |
| 권한 확인 | 슈퍼 관리자 전용 기능 | role !== 'super_admin' → 접근 차단 |
| 로그인 실패 | 잘못된 자격 증명 | 에러 메시지 표시 |
| 연속 실패 | 서버에서 제한 | "잠시 후 다시 시도" 메시지 |

### 라우트 보호 규칙
| 앱 | 보호 대상 | 미인증 시 |
|----|----------|----------|
| 고객앱 | 메뉴, 장바구니, 주문 페이지 | 설정 화면으로 리다이렉트 |
| 관리자앱 | 대시보드, 관리 페이지 | 로그인 화면으로 리다이렉트 |
| 관리자앱 | 관리자 계정 관리 | role 확인 → 슈퍼 관리자만 접근 |

## 3. 폼 검증 규칙

### 메뉴 등록/수정 폼
| 필드 | 규칙 | 에러 메시지 |
|------|------|------------|
| 메뉴명 | 필수, 1~50자 | "메뉴명을 입력해주세요" / "50자 이내로 입력해주세요" |
| 가격 | 필수, 숫자, 100~1,000,000 | "가격을 입력해주세요" / "100원~1,000,000원 사이로 입력해주세요" |
| 설명 | 선택, 최대 200자 | "200자 이내로 입력해주세요" |
| 카테고리 | 필수 선택 | "카테고리를 선택해주세요" |
| 이미지 URL | 선택, URL 형식 | "올바른 URL 형식으로 입력해주세요" |

### 관리자 계정 생성 폼
| 필드 | 규칙 | 에러 메시지 |
|------|------|------------|
| 사용자명 | 필수, 4~20자, 영문+숫자 | "4~20자 영문/숫자로 입력해주세요" |
| 비밀번호 | 필수, 8~30자 | "8자 이상 입력해주세요" |
| 비밀번호 확인 | 비밀번호와 일치 | "비밀번호가 일치하지 않습니다" |
| 매장 할당 | 최소 1개 선택 | "매장을 선택해주세요" |

### 테이블 초기 설정 폼
| 필드 | 규칙 | 에러 메시지 |
|------|------|------------|
| 매장 코드 | 필수 | "매장 코드를 입력해주세요" |
| 테이블 번호 | 필수, 숫자, 1~999 | "테이블 번호를 입력해주세요" |
| 비밀번호 | 필수, 4~20자 | "비밀번호를 입력해주세요" |

### 카테고리 생성 폼
| 필드 | 규칙 | 에러 메시지 |
|------|------|------------|
| 카테고리명 | 필수, 1~30자 | "카테고리명을 입력해주세요" |

## 4. UI 동작 규칙

### 주문 성공 플로우
1. 주문 확정 버튼 클릭
2. 로딩 표시 (버튼 비활성화)
3. 성공 시: 주문 번호 표시 화면 → 5초 카운트다운 → 메뉴 화면 자동 이동
4. 실패 시: 에러 메시지 토스트 → 장바구니 유지 → 재시도 가능

### 확인 팝업 규칙 (관리자)
| 액션 | 팝업 메시지 | 확인 버튼 |
|------|------------|----------|
| 주문 삭제 | "이 주문을 삭제하시겠습니까?" | "삭제" (빨간색) |
| 이용 완료 | "테이블 {N}번 이용 완료 처리하시겠습니까?\n현재 주문이 과거 이력으로 이동됩니다." | "완료 처리" |
| 메뉴 삭제 | "'{메뉴명}' 메뉴를 삭제하시겠습니까?" | "삭제" (빨간색) |
| 장바구니 비우기 | "장바구니를 비우시겠습니까?" | "비우기" |

### 피드백 규칙
| 상황 | 피드백 방식 | 지속 시간 |
|------|-----------|----------|
| 성공 (CRUD) | 초록색 토스트 | 3초 |
| 실패 (에러) | 빨간색 토스트 | 5초 |
| 로딩 중 | 버튼 스피너 + 비활성화 | 완료까지 |
| 네트워크 에러 | 상단 배너 | 연결 복구까지 |

## 5. 데이터 표시 규칙

### 금액 표시
- 형식: `₩{금액}` (천 단위 콤마)
- 예: ₩12,000 / ₩1,500,000

### 시간 표시
- 주문 시각: `HH:mm` (오늘) / `MM/DD HH:mm` (이전 날짜)
- 과거 이력: `YYYY-MM-DD HH:mm`

### 빈 상태 표시
| 화면 | 빈 상태 메시지 |
|------|---------------|
| 장바구니 | "장바구니가 비어있습니다" |
| 주문 내역 | "아직 주문 내역이 없습니다" |
| 대시보드 (주문 없음) | "현재 주문이 없습니다" |
| 과거 이력 | "과거 주문 내역이 없습니다" |
| 메뉴 목록 | "등록된 메뉴가 없습니다" |
